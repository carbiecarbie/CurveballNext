# M5 maintainer physical acceptance

This guide prepares acceptance after an independently reviewed, separately authorized deployment. No human physical acceptance was performed by the implementation agent. Two tabs/automated clients are insufficient.

1. Use two physical computers on **different networks**, ideally Brazil fixed broadband and a hotspot/different carrier. Confirm they are not behind the same router. Record date, build/rules/protocol, `gru` region, browsers (include Edge/Chrome), real mice, display refresh rates and coarse network types. Do not retain IPs, credentials or public room codes in shared evidence.
2. Confirm the actual routes fit RTT≤100 ms, one-way variation≤20 ms, packet loss≤1%, bandwidth≥1 Mbit/s. Preserve clock-offset intervals and outliers. If outside support, retain the limitation and repeat with a qualifying pair; do not shrink the support envelope.
3. Create/invite/join; verify exactly two slots and both Ready, 3-second locked countdown, centered automatic serve, cyan own near paddle/magenta opponent and relative mouse right/down. Try a third browser join race (exactly one vacant slot wins), Full/invalid/deleted codes, and pre-match leave/refresh. Remaining readiness resets and the remaining player keeps their slot.
4. Play at least **ten complete matches** with both initial serving orientations, real curves, diagonal/wall returns, both sides losing lives3→2→1→0, and mutual rematches. Observe19-tick miss hold then90-tick centered countdown with the missed player serving. No extra score/levels/AI, no double loss, one result. Record every match and both perspectives; both independently accept each rematch. Alternation is the previous match's initial serve, not its final rally's serve.
5. Keep one page visibly blurred but responsive for **30 seconds**. The match and genuine losses continue with the last applied target. Repeated rapid blur/focus toggles neither pause nor extend timers. Queue mouse movement before/during return: no old target jump; control stays fenced through sync→processed-state resume→enabled acknowledgement until a newly captured mouse sample. Repeat around rally reset, last life, and return during MatchEnded followed by rematch.
6. Separately hide a page; it closes rather than pausing. Test explicit Leave, refresh, unplug/offline and one-way disruption. The peer sees interruption/no contest on server detection. Check five-second runtime detection, ≤100 ms healthy watchdog wake and ownership/socket cleanup within one further second. Automatic network pongs must not keep a frozen game runtime alive. Waiting/MatchEnded stay healthy without gameplay ticks advancing.
7. Test final delivery in both orders: finish validated/applied then close/backend restart retains that session's winner; server finish lost before valid delivery yields interruption/outcome unknown for that client. A queued valid current-match terminal frame can establish knowledge while closing without reopening controls. Hidden/leave detected before final contact aborts; after server finish cannot change that server result. Ordinary blur does not cancel a final loss. Refresh provides no recovery promise.
8. Exercise ≥64 KiB sustained backpressure and256 KiB/queue caps in the controlled harness: distinct2-second congestion failure, no focus-based extension, bounded stale/frozen world display and no invented contacts. Check Waiting10-minute expiry, result60-second expiry and absolute1-hour TTL separately. Use a controlled/staging session so these intentional failures do not surprise other players.
9. For every disputed contact retain **both screen clips**, exact incoming frame and preceding image, raw draw rectangles, authoritative C−1/C, event/match/rally IDs, input capture/send/receipt/consumption/first-use times and source generations, correction/age counters and clock uncertainty. Inspect before event-driven correction; do not substitute the corrected paddle. Investigate every dispute. Both testers explicitly approve responsiveness, perceived contact fairness and interruption/result clarity within support.
10. Attach the ten-match log and both approvals to independent review, alongside all separate C0/C1/C2/C3/C4a/C4b/C5a/C5b × A/B controlled cells (N≥300 and clear apparent rejection≤1%, complete images/timing and investigated rejections). Physical matches neither replace nor populate those denominators. Failed/ambiguous controlled cells, either tester's disapproval, incomplete deployed soak or unavailable São Paulo placement block release/closure. Physics/rewind/network-envelope changes need a targeted plan revision; do not lower thresholds or remove difficult samples.

Retain evidence privately/redacted, including failure runs. A maintainer must explicitly record final acceptance only after independent implementation review and every deployed/controlled/physical gate passes.
